# ONTAP Storage Setup

The launch form does not show run or skip switches. Leave a section blank and that task stays skipped. Enter values and that task runs. The FIPS dropdown is the exception: it defaults to false and that task runs on every launch.

Required fields are the agent, cluster management address, and password. The username defaults to admin. You can click Next and Finish with only those filled in.

Storage failover, cluster HA, cluster-management auto-revert, spare-disk zeroing, CDP, LLDP, and default broadcast-domain cleanup do not have their own fields. Every launch discovers the cluster nodes, enables storage failover on each node, and sets cluster HA only when that discovery finds exactly two nodes. It also finds the cluster management interface and enables auto-revert on it, zeros spare disks, and enables CDP and LLDP. It deletes an autogenerated Default broadcast domain when that domain is in the Default IPspace, its name starts with `Default-`, and it contains no cluster or node-management port.

Node configuration is one table. Each row is one node, so the node name is entered once. That row has separate columns for the service-processor address, data ports, aggregate name, and disk count. One aggregate is created on that node. To skip the service-processor, aggregate, interface-group, and data-port tasks, delete every row. A blank row still counts as a row, and Finish stays disabled until that row is filled in or deleted. Those same rows are the nodes used for VLANs. A VLAN is created on a node when that row lists data ports, because that is where the interface group exists. The aggregate name on each row is also assigned to the SVM when an SVM name is set.

Network Configuration holds the interface group name and mode, and the IPspace name. The interface group name defaults to `a0a`. You can change it. The mode defaults to `multimode_lacp`. The dropdown also offers `multimode` and `singlemode`. Each node that lists data ports gets that interface group, those ports are added to it, and the group MTU is set to 9000. Traffic is distributed by port. The same name and mode are used on every node. The mode is applied when the group is created. Clear the name to skip only the interface group. A blank IPspace name does not skip it. The other node-configuration tasks still run.

That same section also holds the VLAN name and VLAN ID for in-band management, NFS, iSCSI fabric A, and iSCSI fabric B. In-band management is the management VLAN. NFS is storage protocol NFS. iSCSI-A is storage protocol iSCSI on fabric A, and iSCSI-B is storage protocol iSCSI on fabric B. Leave the IPspace name blank to skip IPspace, broadcast domain, and VLAN creation. The interface group task still runs from its own name and the node data ports. The IPspace task does not wait for the interface group. An IPspace name on its own creates that IPspace. The broadcast-domain task runs after the IPspace task. It creates a broadcast domain for each network whose VLAN name is set, and it does not read the VLAN ID. Leave a VLAN name blank to skip that broadcast domain. A VLAN name problem does not fail the IPspace task. When the interface group name is set, a node row lists data ports, and that network also has a VLAN ID, the VLAN interface task creates that VLAN on the interface group and adds it to the broadcast domain. That task runs after the broadcast domains and the interface group. The VLAN ID, the interface group name, and the node names are checked there. Leave a VLAN ID blank to skip that VLAN interface. The broadcast domain is still created. ONTAP names the interface `<interface group>-<VLAN ID>`, for example `a0a-1022`. In-band management uses MTU 1500. NFS and both iSCSI VLANs use MTU 9000. A blank interface group name, or node rows with no data ports, skips the VLAN interfaces. The broadcast domains for the filled-in networks are still created.

SVM Configuration creates one SVM. Enter the SVM name to run it. Leave that name blank and the SVM task stays skipped, along with the load-sharing SnapMirror, vsadmin, the SVM login banner, the management LIF, the default route, and SVM DNS. The SVM is created in the IPspace from Network Configuration, so that name has to be filled in. The SVM task waits for the IPspace and the aggregates. It does not wait for the VLAN interfaces. The aggregate names from the node configuration rows are assigned to the SVM, so those rows need at least one aggregate name. The protocol dropdown lists nfs and iscsi and starts with nothing selected. Choose nfs, iscsi, or both. nfs starts the NFS service with NFSv3 and NFSv4.1 enabled and UDP disabled. iscsi starts the iSCSI service. Those steps are part of the SVM task.

The load-sharing SnapMirror of the SVM root volume is its own task. It runs after the SVM task when the SVM name and the job name or job minutes are set. It creates the mirror volumes, then the job schedule, then the SnapMirror relationship. Both the job name and the job minutes are required. The schedule name defaults to `15min` and the minutes default to `0,15,30,45`, which runs at minute 0, 15, 30, and 45 of every hour. Other 15-minute examples are `5,20,35,50` and `7,22,37,52`. Clear both the job name and the minutes to skip the mirror volumes, the schedule, and the SnapMirror relationship. Set only one and this task fails at the schedule, after the mirror volumes are created. An invalid job name or invalid job minutes fail this task the same way. The SVM task is already done, so vsadmin, the banner, the management LIF, the route, and SVM DNS still run. This task reads the node that hosts the SVM root volume from the cluster. Every node row that names an aggregate needs a node name, each node can appear only once, and one of those rows must be the root volume's node. Mirrors are 1 GB data-protection volumes, created on the aggregates from the node rows that are not on that same node. The SnapMirror relationship is load-sharing, initialized, and uses the job schedule. When every aggregate from the node rows is already on the root volume's node, the mirrors and the relationship are skipped. The schedule is still created when its fields are filled in.

The vsadmin password is its own task. It runs after the SVM task. When the password is filled in, it is set on vsadmin and the account is unlocked for http, ontapi, and ssh. Leave it blank to skip that task and leave vsadmin unchanged. The SVM login banner is its own task and runs after the SVM task. It is set when that text is filled in. Leave it blank to skip the banner.

SVM management LIF is its own task. It runs after the SVM task and the VLAN interface task. It is four fields: `svm_mgmt_lif_name`, `svm_mgmt_lif_address`, `svm_mgmt_lif_netmask`, and `svm_mgmt_lif_gateway`. One SVM has one management LIF, so there is no control to add another. Example: `svm_mgmt_lif_name` `svm-mgmt`, `svm_mgmt_lif_address` `10.102.2.50`, `svm_mgmt_lif_netmask` `255.255.255.0`, `svm_mgmt_lif_gateway` `10.102.2.254`. Leave `svm_mgmt_lif_name`, `svm_mgmt_lif_address`, or `svm_mgmt_lif_netmask` blank to skip the LIF. Leave the interface group name or the in-band management VLAN name or VLAN ID blank to skip it as well. Leave `svm_mgmt_lif_gateway` blank to skip the default route. If the LIF is skipped, the route is skipped as well. The LIF is created when `svm_mgmt_lif_name`, `svm_mgmt_lif_address`, and `svm_mgmt_lif_netmask` are all filled in and the interface group and in-band management VLAN are filled in. At least one node row must list data ports. The interface group and the VLAN interface are created only on those nodes, so with no data ports both of those tasks finish without creating the home port. The LIF task then fails before it calls the cluster. Add data ports to a node row, or clear the LIF fields to skip it. Leave the SVM name blank and the LIF, the default route, and SVM DNS are skipped with the SVM task.

The LIF task reads the node that hosts the SVM root volume from the cluster: the root volume is found, its aggregate is read, and the aggregate reports the node. The home port is not entered on the form. It is the in-band management VLAN interface from Network Configuration. The interface group name and the in-band management VLAN ID are joined with a hyphen. Interface group `a0a` and VLAN ID `2235` make home port `a0a-2235`. The VLAN name has to be filled in as well, because that is what creates the VLAN interface. If the interface group name, the VLAN name, or the VLAN ID is blank, LIF creation is skipped. The LIF uses service policy `default-management`, admin status up, failover policy `broadcast-domain-wide`, and auto-revert. The default route is its own task. It runs after the LIF task. When `svm_mgmt_lif_gateway` is filled in and the LIF fields are filled in, that gateway is added as the SVM default route, destination `0.0.0.0/0`. A blank gateway skips the route. If the LIF is skipped, the route is skipped as well.

SVM DNS is its own task. It runs after the default route. The default route runs after the management LIF, and that LIF runs after the SVM task. It is two fields: `svm_dns_servers` and `svm_dns_domain`. `svm_dns_servers` is a comma-separated list of IPv4 addresses, for example `10.1.1.10,10.1.1.11`. `svm_dns_domain` is the DNS domain name, for example `example.com`. These are separate from the cluster DNS domain and DNS servers. Fill in both to configure DNS on the SVM. Leave both blank to skip it. Set only one and the SVM DNS task fails. The SVM task is already done.

Cluster name is used by the location, timezone, and HTTP tasks. It must exactly match the cluster's current name. Entering a different value renames the cluster when location or timezone runs. When the cluster name is filled in, HTTP is removed from the cluster default-management service policy. HTTPS, SSH, and the other services on that policy stay in place. Leave the cluster name blank to skip location, timezone, and this HTTP task.

| Filled in | Task that runs |
| --- | --- |
| Cluster name and location | Update cluster location |
| Node configuration rows | Configure each node's service processor, disable flow control on its data ports, discover the disk class, and create one aggregate on that node. Those aggregate names are assigned to the SVM when an SVM name is set |
| Interface group name, mode, and data ports | Create that interface group on each node that lists data ports, add those ports, and set the group MTU to 9000. The name defaults to `a0a` and the mode defaults to `multimode_lacp`. Clear the name to skip this task. A blank IPspace name does not skip it |
| IPspace name | Create that IPspace. This task does not wait for the interface group. Leave the IPspace name blank to skip IPspace, broadcast-domain, and VLAN creation. The interface group task still runs |
| IPspace name and a VLAN name | Create that network's broadcast domain after the IPspace task. The VLAN ID is not used. In-band management uses MTU 1500. NFS uses MTU 9000. iSCSI fabric A and iSCSI fabric B each use MTU 9000. Leave that VLAN name blank to skip it. A VLAN name problem does not fail the IPspace task |
| IPspace name, a VLAN name and VLAN ID, the interface group name, and node rows that list data ports | Add that VLAN to the interface group on each of those nodes. This task runs after the broadcast domains and the interface group. Leave the VLAN ID blank to skip the VLAN interface. The broadcast domain is still created. Leave the interface group name blank, or list no data ports, and the VLAN interfaces are skipped |
| SVM name, the IPspace name, at least one aggregate name on the node rows, and nfs, iscsi, or both | Create the SVM in that IPspace, assign those aggregates, and allow the selected protocols. This task waits for the IPspace and the aggregates. nfs starts NFSv3 and NFSv4.1 and disables UDP. iscsi starts the iSCSI service. Leave the SVM name blank to skip the SVM and the tasks that follow it. The protocol dropdown starts empty; choose nfs, iscsi, or both |
| SVM name, job name, and job minutes | Create the load-sharing SnapMirror of the SVM root volume after the SVM task. Both the job name and the job minutes are required. The schedule defaults to `15min` and `0,15,30,45`. Create a 1 GB load-sharing mirror on each aggregate that is not on the root volume's node, then create the job schedule, then initialize the load-sharing SnapMirror relationship that uses that schedule. Clear both job fields to skip the mirrors, the schedule, and the relationship. Set only one and this task fails at the schedule |
| SVM name and vsadmin password | Set the vsadmin password and unlock vsadmin for http, ontapi, and ssh. This task runs after the SVM task. Leave the password blank to leave vsadmin unchanged |
| SVM name and SVM login banner | Set the SVM login banner after the SVM task. Leave it blank to skip the banner |
| SVM name, svm_mgmt_lif_name, svm_mgmt_lif_address, and svm_mgmt_lif_netmask, plus the interface group name, the in-band management VLAN name and VLAN ID, and data ports on a node row | Create the SVM management LIF on the node that hosts the SVM root volume. This task runs after the SVM and the VLAN interfaces. The home port is `<interface group>-<VLAN ID>`, for example `a0a-2235`. Leave svm_mgmt_lif_name, svm_mgmt_lif_address, or svm_mgmt_lif_netmask blank to skip the LIF. Leave the interface group or the in-band management VLAN blank to skip it as well. With no data ports on any node row this task fails before it calls the cluster. Leave the SVM name blank to skip it with the SVM task |
| SVM name, the SVM management LIF fields, and svm_mgmt_lif_gateway | Create the SVM default route `0.0.0.0/0` through that gateway. This task runs after the management LIF. Leave svm_mgmt_lif_gateway blank, or skip the LIF, and the route is skipped. Leave the SVM name blank to skip it with the SVM task |
| SVM name and both svm_dns_servers and svm_dns_domain | Configure DNS on the SVM after the default route. The default route runs after the management LIF, and that LIF runs after the SVM task. Example servers `10.1.1.10,10.1.1.11` and domain `example.com`. Leave both fields blank to skip SVM DNS. Set only one and the SVM DNS task fails. These fields are separate from cluster DNS |
| DNS domain and DNS servers | Configure cluster DNS |
| NTP servers | Configure NTP |
| Cluster name and timezone | Set the timezone |
| Cluster name | Disable HTTP cluster management. This removes management-http from the default-management service policy on that cluster. Leave the cluster name blank to skip this task |
| AutoSupport mail settings | Configure AutoSupport on the nodes discovered from the cluster |
| Legacy license keys or NLF contents | Add licenses |
| FIPS dropdown | Set SSL FIPS mode on every launch. The dropdown defaults to `false`, which matches a new ONTAP cluster. Choose `true` to enable FIPS-compliant SSL |
| Any of SNMP contact, location, community, traphost, or SNMPv3 user | Configure and enable SNMP. Contact, location, and the SNMPv3 user each apply only when that field is filled, so leaving location or traphost blank does not skip the rest. Authentication and privacy are chosen independently, and both password fields stay on the form. With FIPS `false`, authentication is `none`, `md5`, `sha`, or `sha2_256` and privacy is `none`, `des`, or `aes128`. A password is required for each protocol that is not `none` when an SNMPv3 user is set. Community and traphost apply only when FIPS is `false` and that field is filled. With FIPS `true`, the form shows `sha` or `sha2_256` for authentication and `aes128` for privacy, and both passwords are required when an SNMPv3 user is set |
| Login banner text | Set the login banner |
